# Spec 07 — HTML Backtest Report (`internal/report/html_report.go`)

## Overview

PRD §4.3 (SHOULD, not MUST) wants a static HTML report per backtest — equity curve, drawdown chart, monthly
P&L heatmap, full trade list — for analysis beyond what fits in a terminal. This spec defines the generator
and resolves the blueprint's open question ("generated every run, or only on `[h]` key request?") with a
concrete default, since Spec 10's persistence/orchestration needs a definite call site.

## Current Behavior (verified)

- No `internal/report` package exists (confirmed by directory listing).
- No HTML templating dependency exists in `go.mod` beyond Go's own standard-library `html/template`, which
  is sufficient for this spec's needs (no new third-party templating dependency required).

## Target Behavior

```go
// internal/report/html_report.go
package report

import "go-trade-bot/internal/metrics_provider"

// Generate renders a single self-contained HTML file (inline CSS/JS, no
// external asset fetches - matches this project's homelab/offline-friendly
// posture) summarizing one backtest run, and returns the path it wrote to.
func Generate(outputDir string, run BacktestReportInput) (path string, err error)

type BacktestReportInput struct {
    StrategyName string
    Symbol       string
    StartDate    time.Time
    EndDate      time.Time
    Metrics      metrics_provider.BacktestMetrics
    Trades       []metrics_provider.TradeLogEntry
}
```

Report sections, per PRD §4.3/§4.5 Page 5: equity curve (line chart from `Metrics.EquityCurve`), drawdown
curve (derived from the same equity curve, rendered as an "underwater" chart — percentage below running
peak over time), monthly P&L heatmap (trades bucketed by calendar month, summed), and a full trade table
(entry/exit time, price, P&L, duration, exit reason). Charts are rendered as inline SVG generated by Go code
(no JS charting library dependency, keeping the report a single static file with zero external requests —
consistent with the homelab's offline/low-dependency posture already established for TUI/backend choices).

**File naming/location**: `outputDir/{strategy_name}_{symbol}_{run_id}.html`, where `outputDir` is a
configured path (e.g. `./reports/backtests/`) — `run_id` ties the file back to Spec 10's persisted
`BacktestRun.ID`, so `BacktestRun.HTMLReportPath` (blueprint §3.3's ERD) can store this exact path.

### Generation frequency — resolved default (judgment call)

**Decision: generate on every completed backtest run, not only on an explicit on-demand request.**
Rationale:
- A backtest run is already an explicit, operator-initiated action (via `cmd/backtest` or the API endpoint,
  Spec 10) — unlike a live per-cycle event that could fire thousands of times a day, a backtest run happens
  at human-supervised cadence (dozens per research session, not per-candle), so "every run" does not create
  the runaway-disk-usage scenario the blueprint's open question worried about.
- Generating synchronously as part of the run (not deferred to a later on-demand key-press) means Phase 3's
  TUI `[h]` keybinding only ever needs to **open** an already-existing file, never wait on report generation
  — better UX, and it decouples the TUI (which doesn't exist yet) from this spec's completion.
- Disk usage is bounded by a **retention policy** instead of by gating generation: Spec 10's persistence
  layer keeps the last N (default 20, configurable) `BacktestRun` rows *with* HTML reports per strategy,
  deleting the oldest report file (not the DB row — the row's metrics stay queryable for history/comparison
  even after its HTML file is pruned) once the limit is exceeded.

## Acceptance Criteria

1. **Given** a completed backtest run with 15 trades, **when** `Generate` is called, **then** it produces a
   single `.html` file under `outputDir` containing all four sections (equity curve, drawdown, monthly
   heatmap, trade table) with no broken/missing chart for any section, even if one section's data is sparse.
2. **Given** a backtest with zero trades (Spec 06 Acceptance Criterion #6's empty case), **when** `Generate`
   is called, **then** it still produces a valid HTML file — the trade table renders as "no trades executed
   in this run" rather than an empty/broken table, and the equity curve renders as a flat line at the
   starting balance.
3. **Given** `Metrics.ProfitFactor == +Inf` (Spec 06 Acceptance Criterion #2's case), **when** the report
   renders the top metrics row, **then** it displays `"∞"` or `"N/A (no losing trades)"` rather than a raw
   `+Inf` string artifact or a template-rendering error.
4. **Given** the report file already exists at the computed path (e.g. a re-run with the same `run_id`,
   which shouldn't normally happen since `run_id` is a new DB primary key each time, but could occur if a
   run is explicitly re-generated), **when** `Generate` is called again, **then** it overwrites the existing
   file cleanly rather than erroring or appending.
5. **Given** the report is opened in a browser with no network access (homelab-realistic scenario), **when**
   viewed, **then** all charts render correctly — verifying the "no external asset fetches" design
   constraint is actually met, not just intended.
6. **Edge case — very large trade count**: **given** a backtest with several thousand trades (a
   high-frequency Grid strategy over 2 years), **when** `Generate` renders the full trade table, **then**
   the resulting HTML file remains reasonably sized/browsable (consider pagination or a collapsed/
   virtualized table if the trade count exceeds a threshold, e.g. 500 rows) rather than producing an
   unwieldy multi-megabyte single-page table that's impractical to scroll.
7. **Edge case — report generation failure doesn't fail the backtest**: **given** `Generate` encounters an
   error (e.g. disk full, permission denied on `outputDir`), **when** this occurs, **then** Spec 10's
   orchestration logs the failure and still persists the `BacktestRun`'s computed metrics with
   `HTMLReportPath` left empty — a report-writing failure must never discard an otherwise-successful
   backtest's numeric results.

## Out of Scope

- Interactive charts (zoom/pan/hover tooltips via JS) — inline static SVG only, per the "no external
  requests" design constraint; a JS charting library would also violate that constraint if it needed CDN
  assets, and bundling one inline is more complexity than PRD §4.3's SHOULD-priority feature warrants.
- PDF export or any format beyond HTML — not requested.
- The retention-policy deletion logic itself — that's specified as part of Spec 10 (persistence layer),
  this spec only defines what `Generate` produces and where.

## Dependencies

- Spec 06 (Metrics Provider ACL) — `BacktestMetrics`/`TradeLogEntry` are this spec's direct inputs.
- Spec 10 (Backtest Persistence and API) — supplies `run_id` for file naming and owns the retention policy
  referenced above.
